# Proposal 0001: PRI v0.1 Runtime Contract

## Problem

The first PRI draft defined a Promotion document, but a public launch contract
needs to be useful as more than a single intent YAML file. Implementers need a
portable way to describe artifacts, checks, evidence, runtime outcomes, and
conformance without adopting a specific platform.

## Proposal

Make PRI v0.1 the first strict runtime contract:

- `Promotion` includes required `spec.unit`, non-empty `spec.artifacts`, and
  non-empty `spec.targets`.
- `Promotion` can optionally include `plan`, `checks`, and `evidence`.
- `PromotionRun` records portable runtime state.
- `CheckResult` and `TargetResult` use closed portable phase enums.
- `implementationPhase` preserves native phase values without weakening
  portable phases.
- `ConformanceProfile` records `adoptionMode` as `native`, `emission`, or
  `bridge`.
- Semantic runtime operations are documented without requiring a transport,
  controller model, RPC protocol, or CLI.

## Compatibility

This replaces the initial placeholder v0.1 shape before external adoption. The
older `spec.version` field is replaced by `spec.artifacts[]`.

## Alternatives Considered

- Keep v0.1 minimal and move runtime semantics to v0.2. Rejected because the
  first public contract should show the real model.
- Relax required fields for adapter convenience. Rejected because adapters and
  bindings should translate native data into strict PRI documents.
- Add a required remote protocol. Rejected because real implementations should
  shape any future remote protocol.

## Open Questions

- Whether richer plan structure should become portable in a later version.
- Whether check enforcement needs more than `required: true|false`.
- Which bindings should be standardized first after v0.1.
